| 2026-08-10 | Pattern rules match the WHOLE path, case-insensitively, for both wildcard and regex kinds | Predictable exact-match semantics mirroring Shopify's redirect matching; partial-match regex would surprise merchants and widen the auto-heal blast radius |
| 2026-08-10 | Merchant regex ReDoS gate = redos-detector analyzer (pure-JS, server-only), after 3 hand-rolled heuristics each got bypassed | Rounds 2/3/4 each bypassed a bespoke heuristic by a sibling shape: nested alternation ((a\|a)), nested-optional ((a?){30}), then ambiguous internal partition ((a+a)+, (.*a)+ — 72s at 33 chars, defeats the last-token-quantified scanner). The general condition is character-set-overlap analysis, too complex to hand-roll safely (reviewer: "plan as its own task, not a 4th ad-hoc patch"). Resolution: redos-detector (deps: regjsparser only — no native build, unlike RE2) analyzes the automaton; verified across ~50 adversarial patterns that it rejects all bypass shapes (incl. all 4 rounds' bypasses) and passes legit URL patterns, with no accepted-but-slow pattern found. Runs server-side ONLY (regex-safety.server.ts, gated in createPatternRule) so it never enters the client bundle — confirmed absent from build/client. The pure paren-scanner stays as a cheap client-preview pre-filter; the 200-char match cap stays as belt-and-suspenders |
| 2026-08-10 | redos-detector analysis timeout = 250ms, and it fails CLOSED (timeout → safe:false) | 1000ms made the test suite exceed vitest's 5s per-test limit (several unsafe patterns each burning ~1s). Verified redos-detector returns safe:false on timeout, so a shorter budget can only reject MORE, never admit a dangerous pattern — 250ms classifies real URL patterns fine and bounds worst-case rule-creation latency. Unsafe-pattern tests use test.each so no single test() accumulates multiple analysis timeouts |
| 2026-08-10 | Redirect open-redirect gate resolves the target against a probe origin (WHATWG parser), not a character blocklist | Security HIGH reused validateRedirectInput (hand-typed) for machine-substituted targets. Blocklist patching got bypassed twice: "/\evil.com" (round 2, \→/ normalization) then "/<tab>/evil.com" (round 3, WHATWG strips tab/LF/CR). Final: `relativeTargetEscapesOrigin` does `new URL(target, probe).origin !== probe` — delegates ALL normalization to the spec parser, closing the whole escape-trick class at once (verified: rejects \, //, tab/LF/CR variants; accepts absolute https and normal paths). Applied at all three call sites (validateRedirectInput, isSafeTargetShape, matchPatternRule capture clamp). hasEmbeddedUrl kept as a separate tidiness rule for same-origin-but-URL-shaped paths (/news/https://evil.com) |
